## Контекст

Необходимо определить какие части данных интернет-магазина (например, заказы, товары, корзины, история заказов, пользовательские сессии) являются критически важными с точки зрения целостности и скорости обработки

Критически важные коллекции для переноса в Cassandra с точки зрения целостности и скорости обработки

| cart                                 | В пик нагрузки в системе может создаваться много новых сущностей. Критически важно обрабатывать их быстро для сниженя нагрузки на систему              | 

# ADR 10.2: Концептуальная модель данных для Cassandra

## Контекст

Необходимо спроектировать схемы таблиц Cassandra для критически важных сущностей: orders, carts, product_stock. Ключевые требования: равномерное распределение данных и быстрый доступ при экстремальной нагрузке (Black Friday).

---

## Решение

### 1. Таблца carts

```
CREATE TABLE carts (
    session_id UUID,
    cart_id UUID,
    user_id UUID,
    items LIST<FROZEN<map<text, int>>>,
    status TEXT,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    PRIMARY KEY ((session_id), status, cart_id)
);
```

| Ключ          | Поле               | Обоснование                                                                       |
|---------------|--------------------|-----------------------------------------------------------------------------------|
| Partition Key | `session_id`       | Каждая сессия эьл отдельная партиция. Запрос корзины по сессии эьо одно обращение |
| Clustering Key | `status, cart_id`  | Быстрая фильтрация по статусу "active"                                            |

Защита от горячих" партишинов - Session_id уникален для каждого посетителя. Нагрузка распределяется равномерно по всем узлам кластера.
